How the existing suite is pointed at the preview (final review O-I3; the commands are in [qa-checklist.md](qa-checklist.md#3-against-the-deployed-preview-then-production)):

- `E2E_CONFIGURED=1` marks a server that has Supabase configured. The four specs that assume a keyless server (`e2e/admin/admin-pages.spec.ts`, `e2e/admin/admin-security.spec.ts`, `e2e/crawl/public-routes.spec.ts`, `e2e/ops/health.spec.ts`) then expect the configured answers (sign-in redirects, 400 and 401 from the staff APIs, readiness 200). These configured expectations are written from the route code and have **never been run against a configured server**: the first preview run is their first test, and a mismatch there is a spec to correct, not a loosened assertion.
- `VERCEL_AUTOMATION_BYPASS_SECRET` is the project's Protection Bypass for Automation secret. When set, the verifier and Playwright send it as `x-vercel-protection-bypass` on every request to the preview and nowhere else; Playwright then keeps no trace.
