# Bot check (Cloudflare Turnstile) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every public form (activity-pack signup, Contact us, order request) refuses a submission unless Cloudflare Turnstile says a person sent it, without making a parent solve a puzzle.

**Architecture:** A provider-neutral `lib/bot-check/` module holds the configuration rules, the shared field name and copy, and one Turnstile verifier. Each submit pipeline calls one gate after its availability checks and before its rate-limit counters. A client hook loads Cloudflare's script only when a visitor starts using a form, renders an interaction-only widget, and hands a fresh single-use token to each request. With both keys unset, nothing changes: no script, no CSP change, and the request bodies stay the same.

**Tech Stack:** Next.js 16.3.8 App Router, React 19.3.0, zod 4.6.6, vitest 5, Playwright 1.63. Turnstile is hosted (`api.js` v0 and `siteverify` v0), so no npm dependency is added. It is provisioned with wrangler 4.151.3 (`wrangler turnstile widget create`).

**Spec:** this plan. The owner's requests on 2026-10-22: "Put antispam for Bibobay, use Cloudflare"; then, after comparing hCaptcha, "Cloudflare is better, and do it with Cloudflare CLI". Research with sources is in the R214–R223 notes below.

## Global Constraints

- No new npm dependency. Turnstile loads from `https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit&onload=<fn>` exactly; never proxy or self-host it.
- **Names.** Provider-neutral outside `lib/bot-check/turnstile.ts` and `components/forms/bot-check/load-turnstile.ts`. The body field is `botCheckToken`, the env names are `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY`, and the readiness key is `botCheck`.
- **The token.** It is never stored, never logged, never put in a Sentry event, and never echoed in a response. It is at most 2048 characters.
- **The secret.** It is never logged or printed. Only `lib/bot-check/*` (server) reads it.
- **Off means unchanged.** With both keys unset, the page CSP string, every request body, every API answer and the privacy text are byte-identical to `main` at `0df50a3`.
- **Forms never read `process.env`.** The site key reaches them as a server prop (the `analyticsConfig()` pattern, `app/layout.tsx:52,55`).
- **Copy.** Plain, kind and truthful. No "robot", "CAPTCHA", "human verification" or blame. No second `role="status"` inside any form (R199).
- **Citations.** Every Turnstile decision in code carries `// src: <url> · turnstile api v0 (hosted) · 2026-10-22`.
- **Docs.** They pass docs-hygiene: no local paths, and email addresses only @example.com.

## Rulings (owner decisions and this plan's decisions; next free number after this slice: R224)

- **R214.** The provider is Cloudflare Turnstile. The owner chose it over hCaptcha on 2026-10-22: hCaptcha's free plan always shows a challenge, and its no-puzzle mode is Pro, $99+/month. Turnstile is provisioned on the brand account (bibobay.official, R19) with the Cloudflare CLI: `wrangler turnstile widget create` under the scopes `account:read user:read challenge-widgets.write`. Widget settings:
  - name "BIBO Bay forms";
  - `--mode managed`;
  - `--domain bibobay.com`, which also covers `www` ([hostname management](https://developers.cloudflare.com/turnstile/additional-configuration/hostname-management/));
  - no localhost.
- **R215. Configuration states.** The state is computed by `botCheckConfig(env)`:
  - **Off:** both keys are unset or blank. The check is skipped, and the honeypot and rate limits stay.
  - **Misconfigured (fails closed):** one key without the other, a key with the wrong shape, one test key mixed with one real key, or Cloudflare's test keys when `VERCEL_ENV === "production"`. Every submission gets 503 `unavailable` and a reported `*_bot_check_unconfigured` event, and a production build fails, naming the variables but never their values.
  - **On:** both keys set and valid.
  - Why test keys are refused in production: the always-pass test secret accepts any token (probed 2026-10-22: `response=garbage` returned `success:true`, `hostname:"example.com"`, `metadata.result_with_testing_key:true`).
- **R216. Check order.** The check runs after the honeypot, validation and availability checks, and before any rate-limit counter. A visitor's field errors therefore never spend a token. A bot without a token cannot use up a family's per-network count or the contact form's shared hourly cap (R212).
- **R217. Loading.** The script loads on intent only: the first `focusin` or `pointerdown` inside a form, never on page view. Cloudflare sees only people who start filling in a form. Widget options:
  - `appearance: "interaction-only"`, so it is usually invisible;
  - `execution: "render"`;
  - `theme: "light"`;
  - `size`: `"compact"` when the container is under 300 px wide, else `"flexible"` (at 320 px with 16 px gutters, "normal" would overflow);
  - `language: "auto"`;
  - `refresh-expired: "auto"`;
  - `response-field: false`, so the form builds its own JSON.
- **R218. The token.** It is single use and lives 300 s ([server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)).
  - The client calls `reset()` after every request that carried one, whatever the answer.
  - The server sends Cloudflare `secret`, `response` and `idempotency_key` only. There is no `remoteip`: nothing about the visitor leaves our server for this, because the visitor's browser has already talked to Cloudflare directly.
- **R219. Answers.**
  - Refused gives 403 with `BOT_CHECK_MESSAGES.refused`, logs `*_bot_check_refused` at info, and is not reported. Refusals are expected noise.
  - Cloudflare unreachable or a failed secret gives 503 with `BOT_CHECK_MESSAGES.unavailable` (orders reuse their `busy` copy) and a reported `*_bot_check_unavailable`.
  - The verifier calls siteverify with a 5000 ms timeout, then retries once after 500 ms with the same idempotency key, only on a network error, a timeout, HTTP 5xx or `internal-error`.
- **R220. CSP.** Only when the check is on, the page policy gains `frame-src https://challenges.cloudflare.com`. The script is trusted through the existing nonce plus `'strict-dynamic'`: Cloudflare documents nonce plus strict-dynamic as supported ([CSP](https://developers.cloudflare.com/turnstile/reference/content-security-policy/)), and the loader still copies the page nonce onto its script. `connect-src` is unchanged, because pre-clearance is not used.
- **R221. Readiness.** `/api/readiness` reports `botCheck` (state on). It is not part of `ready`.
- **R222. Privacy.** The fallback privacy text gains Cloudflare, but only while the check is on:
  - what Cloudflare receives;
  - when it loads;
  - that it never sees what is typed;
  - the legitimate-interest basis;
  - a link to Cloudflare's [Turnstile Privacy Addendum](https://www.cloudflare.com/turnstile-privacy-policy/).
  `docs/data-protection.md` lists Cloudflare as a processor; legal review is still owed (R30). What Cloudflare stores inside its own frame is not documented, so the text claims nothing about it beyond that addendum.
- **R223. CI and testing.**
  - CI uses Cloudflare's published test keys in a new job only. "Automated browsers are not supported for solving production challenges" ([supported browsers](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)).
  - Every other job keeps both keys unset.
  - Keys are never chosen per request by IP or header (the bypass pattern in Cloudflare's E2E tutorial).

## Review Focus

1. **A parent types a long message, so more than 300 s pass before they press Send.** `refresh-expired: "auto"` renews the token. If they press during the renewal, the submit waits for the new token, up to 15 s, instead of sending an expired one. Pinned in T5 (`expired then renewed`).
2. **Cloudflare wants a click.** The widget turns interactive: the submit must not sit on "Sending…". It stops, shows `BOT_CHECK_MESSAGES.interactive`, and the next press sends once the box is done. Pinned in T5 (`interactive`) and T6 to T8 (copy shown, nothing posted).
3. **The script is blocked**, by a privacy extension, a firewall, or being offline. The form shows `BOT_CHECK_MESSAGES.notLoaded` within 15 s and never hangs. Pinned in T5 (`script error`, `load timeout`).
4. **A retry after a 429, 503 or network failure** must carry a fresh token. The old one was spent, and the order form keeps its `submissionKey` across retries. Pinned in T6 to T8 (`reset after every attempt`, two different tokens in two bodies).
5. **The token leaking into storage or logs.** No repository argument and no log entry contains `botCheckToken` or the token value. Pinned in T2 to T4.

### C3. Server verifier and gate (Task 1)

`lib/bot-check/turnstile.ts` (`server-only`):

```ts
export const SITEVERIFY_URL = "https://challenges.cloudflare.com/turnstile/v0/siteverify";
export type BotCheckVerdict =
  | { outcome: "passed" }
  | { outcome: "refused"; reason: "missing_token" | "rejected" | "hostname" | "action" }
  | { outcome: "unavailable"; reason: "timeout" | "network" | "http" | "malformed_reply" | "secret_rejected" | "bad_request" | "internal_error" };
export interface BotCheckVerifier { verify(token: string | undefined, action: BotCheckAction): Promise<BotCheckVerdict>; }
export function createTurnstileVerifier(
  config: Extract<BotCheckConfig, { state: "on" }>,
  options?: { fetch?: typeof fetch; timeoutMs?: number; retryDelayMs?: number; idempotencyKey?: () => string },
): BotCheckVerifier;
```

- **Request:** JSON POST `{ secret, response, idempotency_key }`. Defaults: `timeoutMs: 5000`, `retryDelayMs: 500`, `idempotencyKey: crypto.randomUUID`.
- **Mapping:**

| Siteverify result | Verdict |
|---|---|
| Empty or absent token | `refused/missing_token`, and no request is sent |
| `missing-input-secret` or `invalid-input-secret` | `unavailable/secret_rejected` |
| `bad-request` | `unavailable/bad_request` |
| `internal-error`, after the retry | `unavailable/internal_error` |
| Any other failure (`invalid-input-response`, `timeout-or-duplicate`, unknown codes, or no codes) | `refused/rejected` |
| Success, real keys, `hostname` ≠ `expectedHostname` (when that is non-null) | `refused/hostname` |
| Success, real keys, `action` ≠ the action passed in | `refused/action` |
| Success, test keys | Neither check (the replies say `example.com` and carry no action) |
| Reply not JSON, or `success` not a boolean | `unavailable/malformed_reply` |
| Non-2xx | `unavailable/http` |

`lib/bot-check/gate.ts` (`server-only`):

```ts
export type BotCheck = { state: "off" } | { state: "misconfigured" } | { state: "on"; verifier: BotCheckVerifier };
export function createBotCheck(env: Env, options?: Parameters<typeof createTurnstileVerifier>[1]): BotCheck;
export type BotCheckGate =
  | { ok: true }
  | { ok: false; status: 403; kind: "refused"; reason: string }
  | { ok: false; status: 503; kind: "unavailable" | "unconfigured"; reason: string };
export async function runBotCheck(check: BotCheck, token: string | undefined, action: BotCheckAction): Promise<BotCheckGate>;
```

### C5. Client (Task 5; the forms use it in Tasks 6–8)

`components/forms/bot-check/load-turnstile.ts`:

```ts
export interface TurnstileApi { render(el: HTMLElement, options: Record<string, unknown>): string; reset(id: string): void; remove(id: string): void; }
export function loadTurnstile(timeoutMs?: number): Promise<TurnstileApi>; // singleton; default 15000 ms; rejects on script error or timeout
```

It injects one `<script async defer>` with the R217 URL and a global `onload` callback named `__bibobayTurnstileOnload`. It copies the nonce from the page (`components/preview/style-nonce.ts` reads it from `script[nonce]`; reuse that reader). A failed load clears the singleton, so a later intent can try again.

`components/forms/bot-check/useBotCheck.ts`:

```ts
export type BotCheckTokenResult = { token: string } | { problem: "interactive" | "unavailable" };
export interface BotCheckHandle {
  enabled: boolean;                                  // siteKey !== null
  containerRef: React.RefObject<HTMLDivElement | null>;
  prepare(): void;                                   // idempotent; loads + renders on first call
  token(): Promise<BotCheckTokenResult>;             // current token, or waits ≤15 s for one
  reset(): void;                                     // after every request that carried a token
}
export function useBotCheck(siteKey: string | null, action: BotCheckAction): BotCheckHandle;
```

- **Callbacks:**
  - `callback(token)` stores the token;
  - `expired-callback` clears it (auto-refresh calls `callback` again);
  - `before-interactive-callback` marks the widget interactive;
  - `after-interactive-callback` clears that mark;
  - `error-callback` marks it errored and returns `true`, which suppresses Turnstile's console warning, because page-health asserts zero console errors.
- **`token()` resolves:**
  - the token, if there is one;
  - `{problem:"interactive"}` at once, if the widget is interactive and has no token;
  - `{problem:"unavailable"}` on an error, a load failure or the 15 s timeout.
- **Unmount** calls `remove(widgetId)`.

`components/forms/bot-check/BotCheckSlot.tsx` renders `<div ref={containerRef} className="bot-check" />`. It is placed directly above the submit button; with the check off it renders `null`. CSS: no reserved height and `max-width: 100%`.

**Form wiring (Tasks 6–8):**
- `onFocusCapture` and `onPointerDownCapture` on the `<form>` call `prepare()`.
- On submit, after client validation passes: if `enabled`, `await token()`.
  - On `problem`, show the matching `BOT_CHECK_MESSAGES` text in the existing error outcome slot and post nothing.
  - Otherwise add `[BOT_CHECK_TOKEN_FIELD]: token` to the body.
- `reset()` runs in `finally` after any request that carried a token.
- A 403 shows `BOT_CHECK_MESSAGES.refused`.
- The new strings join the existing height-reserve wrappers, so the layout does not jump.

## Decisions made during execution (recorded 2026-10-22)

These amend the contracts above. The code and the docs follow them.

- **Hostname mismatch is "unavailable".** With real keys, a missing hostname, or one that differs from `expectedHostname`, gives `unavailable/hostname_mismatch` (503, reported), not `refused/hostname`.
  - Why: it can only mean that `NEXT_PUBLIC_APP_URL` differs from the served host.
  - A silent 403 would turn every family away with no alert.
  - The cost: a token from another bibobay.com host gets a 503 instead of a 403, and both refuse.
- **A misconfigured `BotCheck` carries its `BotCheckProblem`.** The gate reports it as the `reason`.
- **`config.ts` uses relative imports.** `scripts/verify-env.ts` runs it under plain `tsx`, which has no `@/` alias. A review missed this, and the existing build-gate smoke test caught it.
- **`notLoaded` copy:** "The spam check didn't load. Please check your connection and try again." `token()` resets or reloads the widget on the next press, so asking for a reload would lose a long message.
- **C7 privacy paragraph:** it was replaced with wording that names this website's Turnstile key and Cloudflare's own use of the data. It only claims what the site sends: "This website sends Cloudflare nothing you type into the form."
  - The cookie sentence is now: "Cloudflare's script draws the spam check inside a frame it serves; this website sets no cookie for it."
  - Both claims are asserted in the browser by `e2e/bot-check`: no first-party cookie, and a typed sentinel never reaches Cloudflare.
- **Sentry carries no `reason`.** The `reason` lives in the server log line: `reportEvent` forwards only a `code` matching `^[A-Z0-9]{1,16}$`.
- **Turnstile's iframe sits inside a closed shadow root.** Browser tests find it through `page.frames()` and wait on `turnstile.getResponse()`.
- **Each form route sets `maxDuration = 30`.** Verification can take about 10.5 s.
- **The slot no longer adds a grid gap.** The hook exposes `visible` (interactive or errored). An empty slot is a zero-height grid row with a gap on each side, which an own negative margin cannot cancel, so `.lead-form > .bot-check:not([data-visible]) + .lead-form__submit` pulls the button up by one gap while the slot is empty. A visible widget gets normal gaps. `e2e/bot-check` asserts the measured distance.
- **Layer 11, re-decided.** The deferral trigger fired on 2026-10-22: the owner moved the DNS to Cloudflare, with the proxy on.
  - Pre-clearance and the WAF stay off, and `@`/`www` DNS only is recommended (Vercel advises against a reverse proxy).
  - New trigger: the owner keeps the proxy on. Then the client address and the WAF are designed together, because `CF-Connecting-IP` cannot be trusted on Hobby.
- **wrangler login scopes.** The Turnstile login uses `account:read user:read challenge-widgets.write`. The hello@ Email Routing fix needs its own login, with `zone:read email_routing:write`.
